# راهنمای پیاده‌سازی نسخهٔ کنسولی با Python

## هدف

یک برنامهٔ کوچک و خوانا که در ترمینال اجرا شود، پیام کاربر را دریافت کند و گفت‌وگو را تا دستور خروج ادامه دهد. این نسخه باید سریع‌ترین راه اثبات اتصال صحیح به API باشد.

## فناوری و وابستگی‌ها

- Python 3.11 یا جدیدتر؛
- SDK رسمی `openai`؛
- `python-dotenv` برای تجربهٔ محلی ساده‌تر؛
- `pytest` برای تست‌های بدون شبکه.

## ساختار پیشنهادی

```text
apps/console/
├── README.md
├── .env.example
├── pyproject.toml
├── src/
│   └── milo_console/
│       ├── __init__.py
│       ├── main.py
│       ├── config.py
│       ├── chat.py
│       └── errors.py
└── tests/
    ├── test_chat.py
    └── test_config.py
```

برای MVP همین تعداد فایل کافی است. از framework، database یا dependency injection پیچیده استفاده نکنید.

## مسئولیت فایل‌ها

- `config.py`: خواندن و اعتبارسنجی متغیرهای محیطی؛
- `chat.py`: ساخت client، نگهداری تاریخچه و فراخوانی مدل؛
- `errors.py`: تبدیل خطاهای SDK به پیام کاربرپسند؛
- `main.py`: حلقهٔ ورودی/خروجی ترمینال و فرمان‌ها؛
- `tests/`: تست با client جعلی یا mock، بدون مصرف API واقعی.

## تنظیمات محیطی

فایل `.env.example` باید فقط این کلیدها را داشته باشد:

```dotenv
OPENAI_API_KEY=
OPENAI_BASE_URL=
OPENAI_MODEL=
```

قواعد:

- مقدار `OPENAI_API_KEY` و `OPENAI_MODEL` الزامی است.
- `OPENAI_BASE_URL` اختیاری است؛ اگر خالی بود، آن را به سازندهٔ client پاس ندهید.
- URL و model را از داشبورد یا مستندات provider بگیرید.
- مقدار واقعی `.env` هیچ‌وقت commit نشود.

## تصمیم API

برای اتصال مستقیم به OpenAI، `Responses API` مسیر رسمی و پیشنهادی فعلی است. بااین‌حال برخی سرویس‌های OpenAI-compatible فقط `Chat Completions` را کامل پیاده‌سازی می‌کنند. بنابراین:

1. ابتدا قابلیت provider انتخابی را بررسی کنید.
2. اگر `Responses API` پشتیبانی می‌شود، از `client.responses.create(...)` استفاده کنید.
3. در غیر این صورت از `client.chat.completions.create(...)` استفاده کنید.
4. این تفاوت فقط داخل `chat.py` باشد و UI ترمینال به آن وابسته نشود.

برای ساده ماندن پروژه، تنها یکی از این مسیرها را براساس provider واقعی پیاده کنید؛ دو مسیر هم‌زمان برای MVP لازم نیست.

## مدل تاریخچه

ساختار داخلی پیشنهادی:

```python
Message = {"role": "user" | "assistant", "content": str}
```

- system prompt در کد تنظیم شود و کاربر نتواند نقش `system` ارسال کند.
- بعد از دریافت هر پاسخ موفق، پیام کاربر و دستیار هر دو به تاریخچه اضافه شوند.
- در پاسخ ناموفق، پیام نیمه‌کاره به تاریخچه افزوده نشود.
- برای MVP یک سقف ساده مثل آخرین ۲۰ پیام در نظر بگیرید تا ورودی بی‌نهایت رشد نکند.

## فرمان‌های ترمینال

| فرمان | رفتار |
|---|---|
| `exit`، `quit` یا `خروج` | پایان امن برنامه |
| `/clear` | پاک‌کردن تاریخچه و شروع مکالمهٔ تازه |
| `/help` | نمایش فرمان‌های موجود |

هر متن دیگری پیام کاربر محسوب می‌شود.

## لحن مایلو

system prompt کوتاه باشد:

```text
You are MILO, a helpful AI companion in PROJECT_MILO. Reply in the user's language, be clear and concise, and never pretend that you performed actions you did not perform.
```

این prompt هویت محصول را ایجاد می‌کند، ولی نباید پاسخ‌ها را بیش‌ازحد نمایشی یا غیرقابل‌اعتماد کند.

## مدیریت خطا

حداقل این حالت‌ها به پیام ساده تبدیل شوند:

| حالت | پیام پیشنهادی |
|---|---|
| کلید موجود نیست | «کلید API تنظیم نشده است؛ فایل `.env` را بررسی کنید.» |
| احراز هویت ناموفق | «کلید API پذیرفته نشد.» |
| مدل پیدا نشد | «شناسهٔ مدل برای این ارائه‌دهنده معتبر نیست.» |
| محدودیت نرخ | «سرویس موقتاً شلوغ است؛ کمی بعد دوباره تلاش کنید.» |
| timeout/شبکه | «ارتباط با سرویس برقرار نشد؛ اینترنت و Base URL را بررسی کنید.» |
| خطای ناشناخته | پیام عمومی همراه با جزئیات فنی فقط در log توسعه |

کلید API، headerها و متن کامل اشکال داخلی را در خروجی کاربر چاپ نکنید.

## راه‌اندازی مورد انتظار

README برنامه باید فرمان‌های معادل زیر را توضیح دهد:

```powershell
cd apps/console
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
Copy-Item .env.example .env
python -m milo_console.main
pytest
```

اگر سیستم از `python` به‌جای `py` استفاده می‌کند، معادل آن هم ذکر شود.

## تست‌های حداقلی

- نبودن متغیرهای الزامی خطای روشن می‌دهد.
- ورودی خالی API را صدا نمی‌زند.
- پاسخ موفق به تاریخچه اضافه می‌شود.
- خطای provider به پیام کاربرپسند تبدیل می‌شود.
- `/clear` تاریخچه را پاک می‌کند.
- تست‌ها network call واقعی ندارند.
